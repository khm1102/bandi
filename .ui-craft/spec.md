## Surface: 공연 운영 설정 (/performance-management)

**화면 목적**: 운영자가 현재 공연의 준비 상태를 파악하고 **다음 미완료 설정 하나**를 처리한다.

### 콘텐츠 우선순위

- P0 현재 프로젝트 제목·상태 (또는 프로젝트 선택)
- P0 다음에 해야 할 작업 안내 + primary CTA 하나
- P0 준비 단계 진행 목록(체크리스트: 기본 정보 → 회차 → 외부 페이지 → 관람 안내 → 공개 상태)
- P1 섹션 내비게이션(개요·회차·외부 공개·관람 안내) — URL hash로 보존
- P1 회차 목록(시각·신청 기간·입장 시작·상태·접근성)과 회차 sheet
- P1 외부 공개 폼(그룹 5개), 관람 안내 accordion, 공시 연결
- P2 검색·공유 설정(접힌 고급 설정), 프로젝트 수정·상태 변경(보조 액션)

### 데스크톱 와이어프레임

```
┌────────┬──────────────────────────────────────────────────────┐
│ 사이드바 │ 공연 운영 설정                                        │
│ (그룹형) │ [프로젝트 선택 ▾]  2026 1학기 · 햄릿   [제작 중]      │
│        │                                                      │
│        │ 다음에 할 일: 첫 공연 회차를 만들어 주세요               │
│        │ [첫 회차 만들기]  ← primary CTA (하나)                 │
│        │                                                      │
│        │ 준비 진행  ●기본 정보 ●─회차 ○외부 페이지 ○안내 ○공개    │
│        │                                                      │
│        │ [개요] [회차] [외부 공개] [관람 안내]   ← 섹션 탭(hash)  │
│        │ ──────────────────────────────────────────────       │
│        │ (선택된 섹션 본문 — 개요: 상태·기간·체크리스트,          │

│        │  관람 안내: accordion + sticky 저장 바)                │
└────────┴──────────────────────────────────────────────────────┘
```

### 상태

| 상태 | 동작 |
|---|---|
| idle | 프로젝트·회차·페이지·안내 로드 완료, 체크리스트 계산 표시 |
| loading | 최종 레이아웃과 같은 형태의 placeholder(요약 줄·체크리스트 줄·목록 줄) |
| empty | 프로젝트 없음: 설명 + "새 공연 프로젝트 만들기" CTA만. 회차 없음: 이유 + "첫 회차 만들기" |
| error | 실패 원인 + 입력 보존 여부 + "다시 불러오기" 행동. 폼 저장 실패 시 입력 유지 안내 |
| partial | 회차/공시/안내 중 일부 실패 시 성공 영역 유지, 실패 영역만 인라인 오류 + 재시도 |
| success | 저장 후 화면 안에서 마지막 저장 시각·공개 상태 갱신 + 체크리스트 갱신 (토스트는 보조) |
| conflict | 409/상태 전이 오류 시 "다른 곳에서 상태가 바뀌었어요" + 새로고침 행동 |
| unauthorized | 401 시 입력을 지우지 않고 "다시 로그인해야 저장할 수 있어요. 작성한 내용은 이 화면에 남아 있어요." |

### 키보드·포커스

- 섹션 탭: Tab으로 이동, 활성 섹션 `aria-current`. hash 변경 시 섹션 제목으로 포커스 이동.
- 회차 sheet: 열릴 때 첫 입력으로 포커스, Esc 닫기, 닫히면 트리거로 복귀, 포커스 트랩.
- 저장 성공 시 포커스는 저장 버튼에 유지, 결과는 aria-live(짧은 문구)로 안내.
- 이탈 경고: 저장하지 않은 변경이 있으면 beforeunload + 섹션 전환 시 확인.

### 주요 액션 → 성공 후 상태

| 액션 | 성공 후 |
|---|---|
| 프로젝트 생성/수정 (sheet) | sheet 닫힘 → 요약·체크리스트 갱신, "공연 프로젝트를 저장했어요." |
| 프로젝트 상태 변경 (sheet, 영향 설명 포함) | 요약 배지 갱신 + 다음 행동 안내 갱신 |
| 회차 생성/수정 (sheet) | 목록 갱신, 새 회차 행 표시 |
| 회차 상태 변경 (sheet: 현재 상태→변경 후 영향→가능한 다음 상태) | 행 배지 갱신 |
| 접근성 지원 추가/수정/삭제 (회차 sheet 내부) | 회차 행의 접근성 표시 갱신 |
| 외부 페이지 저장 (sticky bar) | 마지막 저장 시각 + 공개 상태 화면 표시 |
| 공개 상태 변경 | 상태 배지 + 공개 페이지 링크 갱신 |
| 관람 안내 저장 (sticky bar) | 마지막 저장 시각 표시, 체크리스트 갱신 |
| 공시 연결/해제 (sheet 선택) | 연결 목록 갱신 |

### 사용 API

- GET `/api/performance-management/projects?limit=100` · POST · PUT `/{id}` · PATCH `/{id}/status`
- GET `/api/performance-management/projects/{id}/rounds` · POST `/rounds` · PUT `/rounds/{id}` · PATCH `/rounds/{id}/status`
- GET/POST `/api/performance-management/rounds/{id}/accessibilities` · PUT `/{aid}` · DELETE `/api/performance-management/accessibilities/{id}`
- GET `/api/performance-page-management` · POST · PUT `/{pageId}` · PATCH `/{pageId}/status`
- GET/PUT viewing-guide: `/api/performance-page-management/projects/{id}/viewing-guide`, PUT `/api/performance-page-management/viewing-guide`
- 공시: GET `/api/performance-page-management/projects/{id}/notices` · POST · DELETE `/{noticeId}`, GET `/api/admin/public-notices?status=&pageSize=100`
- 파일: POST `/api/files/private?domain=performance` (multipart) → POST `/api/files/{fileId}/public-promotions`

### API 부족으로 구현하지 않는 것

- 좌석 준비 상태 체크리스트 항목(좌석 배치 API 없음 — 정책 보류)
- 파일 업로드 후 본문 저장 실패 시 고아 파일 정리(보상 API 없음 — 문서에 기록만)
- 연결 가능 공시 100건 초과 페이징(pageSize=100 한계)
- 마지막 저장 시각의 서버 기준 값(응답에 수정 시각 필드가 없으면 클라이언트 시각으로 표시하고 "이 브라우저 기준"임을 명시)

### 반응형

- 모바일: 1열, 섹션 세그먼트는 4등분 고정(스크롤 없음), 폼 sticky action bar 하단 고정(safe-area 대응)
- md: 폼 2열 그룹, 회차 목록 구조화
- lg: 사이드바 상시 노출, 본문 max-w-4xl (설정 화면은 좁은 컬럼 유지 — 읽기 폭)

### 완료 조건

- 프로젝트 없음/있음, 회차 없음/있음에서 첫 화면이 "다음 행동"을 먼저 보여준다
- 네 섹션이 hash로 전환·복원된다
- 기존 12개 액션(위 표)이 모두 동작한다
- 저장하지 않은 변경 이탈 경고, 중복 제출 방지, 320px 가로 넘침 없음

## Surface: 관람 신청 관리 (/reservations)

**화면 목적**: 운영자가 특정 회차의 신청 상태를 확인하고 **한 신청을 조회·취소하거나 명단을 내보낸다**.

### 콘텐츠 우선순위

- P0 현재 프로젝트·회차 (compact context selector) + 회차 상태
- P0 신청 건수·유효 좌석·입장 좌석·입장률 (compact summary 한 줄)
- P0 상태 필터 + 신청 목록(모바일 세로 리스트)
- P1 신청 상세 sheet(신청번호·이름·연락처·좌석별 상태·취소 가능 여부·취소 시작)
- P1 더 보기(25건 offset), CSV 전체 내보내기
- P2 취소 확인(대상·좌석·현재 상태·취소 후 결과·사유)

### 데스크톱 와이어프레임

```
┌────────┬──────────────────────────────────────────────────────┐
│ 사이드바 │ 관람 신청 관리                       [명단 CSV 내보내기]│
│        │ [프로젝트 ▾] [회차 ▾]  회차 상태: 신청 중               │
│        │ 신청 12건 · 유효 좌석 31석 · 입장 8석 · 입장률 26%       │
│        │ [전체] [확정] [일부 취소] [취소]                        │
│        │ ┌──────────────────────────────────────────────┐    │
│        │ │ 신청번호   관람객   좌석        상태     상세    │    │
│        │ │ R-0012    김관객   A1 A2      확정     [열기]  │    │
│        │ │ …                                            │    │
│        │ └──────────────────────────────────────────────┘    │
│        │              [25건 더 보기]                           │
└────────┴──────────────────────────────────────────────────────┘
                             ┌───────────────┐
                             │ 상세 sheet(우측) │
                             └───────────────┘
```

### 상태

| 상태 | 동작 |
|---|---|
| idle | 목록 25건 + 더 보기 |
| loading | 목록 형태 placeholder 행, 더 보기 진행 중 잠금 |
| empty | 프로젝트/회차 없음: 원인 + 다음 행동(공연 운영 설정으로 이동). 신청 없음: 이유 설명. 필터 결과 없음: "필터 초기화" 행동 |
| error | 목록 로드 실패: 원인 + 재시도. CSV 실패: 다운로드 미생성 + 재시도 |
| partial | 지표 실패·목록 성공(또는 반대) 시 성공 영역 유지, 실패 영역만 재시도 |
| success | 취소 성공 시 sheet 안에 결과 표시 후 목록·지표 갱신 |
| conflict | 취소 대상이 이미 취소됨(4xx) → "이미 처리된 신청이에요" + 새로고침 |
| unauthorized | 401: 입력·필터 유지 안내 + 재로그인 필요 안내 |

### 키보드·포커스

- 목록 행은 button(모바일 카드)·행 내 "열기" 버튼(데스크톱)으로 sheet 열기 — Enter/Space 동작
- sheet: 포커스 트랩·Esc·트리거 복귀
- 취소 완료 후 포커스는 sheet의 결과 영역 → 닫으면 해당 행(삭제된 경우 목록)으로 복귀
- 더 보기: 로드 후 포커스 유지, 새 행 수를 aria-live로 안내

### 주요 액션 → 성공 후 상태

| 액션 | 성공 후 |
|---|---|
| 프로젝트/회차 변경 | 목록·offset 초기화, 지표 갱신 |
| 상태 필터 | 목록·offset 초기화 |
| 더 보기 | 25건 추가, 응답 < 25건이면 "마지막이에요" 표시·버튼 제거 |
| 상세 sheet 열기 | 좌석별 상태·취소 가능 여부 표시 |
| 신청 취소 (sheet 내부: 대상·좌석·현재 상태·취소 후 결과·사유 입력) | sheet 안 성공 표시 → 목록·지표 갱신 |
| CSV 내보내기 | 전 페이지 순차 조회(25건씩) → 완성 후 다운로드, 진행 상태 표시, 실패 시 파일 미생성 |

### 사용 API

- GET `/api/performance-management/projects?limit=100`
- GET `/api/performance-management/projects/{id}/rounds`
- GET `/api/reservation-management/rounds/{roundId}/reservations?projectId&status&offset&limit` (25건씩)
- GET `/api/reservation-management/rounds/{roundId}/metrics?projectId`
- PATCH `/api/reservation-management/reservations/{id}/cancel` {performanceProjectId, reason}

### CSV 규칙

- 선택 회차·필터의 전체 페이지를 25건씩 순차 조회 후 생성 (현재 화면 100건 한계 제거)
- `=`, `+`, `-`, `@` 시작 값 앞에 `'` 추가(수식 주입 방지), 따옴표·쉼표·줄바꿈 RFC 4180 이스케이프, BOM 유지
- 내보내는 동안 버튼 잠금 + "n건 수집 중" 진행 표시, 실패 시 다운로드 미생성 + 재시도

### API 부족으로 구현하지 않는 것

- 검색창(서버 검색 API 없음 — 클라이언트 부분 검색으로 흉내 내지 않음)
- 전체 건수/hasNext 표시(total 없음 — 추측 금지, "마지막" 판단은 응답 < 25건)
- 좌석 준비 필요 상태의 신뢰 표시(관리자용 좌석 조회 API 없음 — 회차의 신청 데이터만으로는 좌석 유무를 단정할 수 없어 표시하지 않음)

### 반응형

- 모바일: 세로 카드 리스트(가로 스크롤 테이블 금지), 행 터치 영역 ≥ 44px
- md 이상: 구조화 목록(그리드 행) — 정렬 없는 단순 열 구조, 클라이언트 정렬은 현재 로드분에만 적용되므로 제공하지 않음(전체 정렬 착시 방지)

### 완료 조건

- 회차 전환·필터·더 보기·상세·취소·CSV가 모두 동작하고 offset 초기화 규칙을 지킨다

### 상태 (result feedback 영역 — 토스트만으로 끝내지 않음)

| 상태 | 표시 |
|---|---|
| 정상 조회 | 관람객·상태·좌석별 상태, 미입장만 선택 가능 |
| 일부 입장 | 남은 좌석 강조 + "이미 입장한 좌석 n석이 있어요" |
| 전원 입장 완료 | "모든 좌석이 이미 입장했어요" + 좌석별 입장 시각 |
| 취소된 신청 | "취소된 신청이에요. 입장 처리할 수 없어요" + 상태 근거 |
| 다른 회차 QR / 불일치 QR | 서버 오류 메시지 기반: "이 회차의 신청이 아니거나 일치하지 않아요" + 회차 확인 안내 (토큰 원문 미표시) |
| 네트워크 오류 | "연결에 실패했어요. 입력한 내용은 지워졌어요(보안)" + 다시 조회 안내 |
| 입장 처리 성공 | "n석 입장을 처리했어요" + 처리 좌석 목록 + [다음 관람객 받기] |
| 입장 처리 충돌 | "다른 기기에서 먼저 처리됐을 수 있어요" + 현재 상태 다시 조회 |
| ENTRY_OPEN 아님 | 입력 비활성 + 이유("이 회차는 아직 입장 시작 전이에요") + 다음 행동(회차 상태 변경은 공연 운영 설정에서) |

### 키보드·포커스

- 회차 선택(ENTRY_OPEN) 후 QR 입력 자동 포커스, 스캐너 입력 → Enter 조회
- 조회 성공 시 포커스는 result 영역 제목 → Tab으로 좌석 선택
- [다음 관람객 받기] → 결과 초기화 + QR 입력 재포커스
- 입장 취소 sheet: 트랩·Esc·복귀
- 모든 좌석 토글은 체크박스(라벨 44px 이상)

### 보안·개인정보

- 토큰 원문을 DOM 텍스트·URL·로그·오류 메시지에 남기지 않음(입력은 type=password 유지, 메모리 변수는 처리 완료·초기화 시 null)
- 조회 종료·초기화 시 입력값과 현재 신청 상태 제거, 다음 관람객로 넘어가면 이전 개인정보 DOM 제거
- 이름·연락처는 result 영역에서만 표시

### 주요 액션 → 성공 후 상태

| 액션 | 성공 후 |
|---|---|
| QR 조회 (Enter) | result 표시, 토큰은 메모리에만 유지 |
| 수동 조회 (신청번호+이름) | 동일한 result·좌석 UI |
| 미입장 좌석 모두 선택 | 선택 요약 갱신, CTA 활성 |
| 선택 좌석 입장 | result 안 성공 표시 + 지표 갱신 + [다음 관람객 받기] |
| 입장 취소 (sheet) | 신청 재조회 + 지표 갱신 |
| 다음 관람객 받기 | 결과·민감정보 초기화 + QR 입력 포커스 |

### 상태·보안

- 신청은 회차→좌석→신청 정보의 3단계이며 현재 단계의 primary CTA만 노출한다.

- 조회 토큰은 URL·localStorage·sessionStorage에 기록하지 않는다. 조회 실패 시 입력값을 유지하고, 성공 시 입력 DOM에서 지운 뒤 메모리에만 둔다.
- 다른 신청 조회와 페이지 이탈 시 이전 관람객 정보와 토큰 참조를 제거한다.
- 공개 공연 페이지는 장식용 영문 eyebrow, 그라디언트, 가짜 공연 정보를 사용하지 않는다.

## Surface group: 인증·오류

대상: `/login`, 403, 404, 500

### 계약

- 로그인은 학번·학교 포털 비밀번호·단일 CTA만 중심에 두고 인증 중 중복 제출을 막는다.
- 비밀번호 보기 상태는 버튼의 `aria-pressed`와 실제 input type을 함께 바꾸며 서버 응답 후 비밀번호를 복원하지 않는다.
- 특정 연도·공연명 같은 목업 정보는 인증 셸에 노출하지 않는다.
- 오류 화면은 HTTP 숫자보다 사용자가 겪은 결과를 제목으로 쓰고, 원인 가능성·데이터 변경 여부·복귀 행동을 제공한다.
- 403은 역할 확인, 404는 주소/공개 기간 확인, 500은 저장 불확실성과 현재 상태 재확인을 각각 안내한다.
