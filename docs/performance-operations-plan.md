# bandi 공연 제작·관람 운영 계획 — 폐기 기록

> 2026-07-21에 공연 제작·콘텐츠·운영·외부 홍보·관람 신청·QR 입장 기능
> 전체가 1차 범위에서 제거됐다. 이 문서의 나머지 내용은 과거 기획 기록이며
> 구현 근거로 사용할 수 없다. 폐기 범위는
> [retired-services.md](retired-services.md)를 따른다.

> 문서 상태: 좌석 배치 정책을 제외한 1차 구현 승인 기준선
> 작성 기준일: 2026-07-18
> 좌석 배치 정책: 별도 기획 완료 전까지 보류

## 1. 확정된 결정

- 공연 제작 프로젝트는 학기당 하나를 운영한다.
- 팀별 제작 업무는 공연 제작 프로젝트 아래에서 파생된다.
- 제작 업무의 담당 단위는 개인이 아니라 팀이다.
- 권한은 운영진, 팀장, 일반 부원으로 구분한다.
- 일반 부원도 소속 팀의 제작 업무를 생성할 수 있다.
- 관람객에게 신청 조회와 신청 취소 기능을 제공한다.
- 공연 당일에는 QR 코드를 이용해 입장 처리한다.
- 좌석 배치 생성·재사용 방식은 별도 기획 결과가 나올 때까지 확정하지 않는다.

## 2. 전체 구조

```text
학기별 공연 제작 프로젝트
├── 팀별 제작 업무
├── 소품·장비 사용
├── 프로젝트 공통 체크리스트
└── 공연 회차
    ├── 회차별 체크리스트
    ├── 좌석
    ├── 관람 신청
    └── QR 입장
```

공연 제작 프로젝트가 내부 제작 업무의 기준이며, 실제 관람 일시는 공연 회차로 분리한다. 한 학기 프로젝트에서 여러 회차를 운영할 수 있다.

## 3. 학기별 공연 제작 프로젝트

### 3.1 기본 정보

- 학년도
- 학기
- 작품명
- 제작 시작일과 종료일
- 공연 장소
- 작품 소개
- 포스터 이미지
- 프로젝트 상태

### 3.2 상태 후보

- 기획 중
- 제작 중
- 관람 신청 중
- 공연 진행 중
- 종료
- 보관

### 3.3 정책

- 같은 동아리에는 동일 학년도·학기의 공연 제작 프로젝트를 하나만 생성한다.
- 종료된 프로젝트의 진행 기록과 체크리스트는 다음 학기 프로젝트와 분리한다.
- 지난 프로젝트는 조회 가능하지만 일반 부원이 수정할 수 없다.
- 특별 공연이나 방학 공연을 학기 프로젝트에 포함할지는 추후 결정한다.

## 4. 팀별 제작 진행 상태

### 4.1 업무 단위

각 제작 업무는 다음 정보를 가진다.

- 공연 제작 프로젝트
- 담당 팀
- 업무 제목
- 설명
- 시작일과 마감일
- 진행 상태
- 차단 사유
- 생성자와 최종 수정자
- 생성·수정 시각

개인 담당자는 지정하지 않는다. 업무 책임은 담당 팀과 해당 팀장 선에서 관리한다.

### 4.2 상태

- 할 일
- 진행 중
- 확인 필요
- 차단됨
- 완료

### 4.3 권한

| 기능 | 일반 부원 | 팀장 | 운영진 |
|---|---|---|---|
| 전체 팀 업무 조회 | 가능 | 가능 | 가능 |
| 소속 팀 업무 생성 | 가능 | 가능 | 가능 |
| 다른 팀 업무 생성 | 불가 | 불가 | 가능 |
| 소속 팀 업무 상태 변경 | 가능 | 가능 | 가능 |
| 소속 팀 전체 업무 수정·삭제 | 본인 생성 업무만 허용하는 안 검토 | 가능 | 가능 |
| 다른 팀 업무 수정·삭제 | 불가 | 불가 | 가능 |

일반 부원의 수정·삭제 범위는 아직 확정하지 않았다. 업무 생성은 허용하되, 팀장이 소속 팀 업무를 최종 정리하고 관리하는 구조를 기본으로 한다.

### 4.4 진행률

- 전체 업무 수 대비 완료 업무 수로 프로젝트 진행률을 계산한다.
- 팀별 진행률을 별도로 표시한다.
- 차단됨과 마감일 초과 업무를 별도 표시한다.
- 업무별 가중치와 팀 간 선후행 관계는 2차 기능으로 둔다.

## 5. 소품·장비

### 5.1 관리 대상

- 수량 중심 품목: 건전지, 케이블, 소모품처럼 같은 종류를 수량으로 관리하는 물품
- 개별 추적 장비: 마이크, 조명 장비, 카메라처럼 개별 상태와 사용자를 추적하는 물품

### 5.2 공통 정보

- 품목명
- 분류
- 소유 구분: 동아리, 부원 개인, 외부 대여
- 보관 위치
- 총수량 또는 개별 관리번호
- 상태
- 현재 사용 팀
- 연결된 공연 제작 프로젝트
- 사진과 비고

### 5.3 상태 후보

- 사용 가능
- 사용 중
- 대여 중
- 수선 중
- 분실
- 폐기

### 5.4 이력

- 대여와 반납
- 보관 위치 변경
- 수선과 파손
- 수량 변경
- 개인 소유 물품의 소유자와 반환 예정일

이력이 있는 품목은 물리 삭제하지 않고 상태를 변경한다. QR·바코드 자산 관리는 1차 범위에서 제외한다.

## 6. 공연 체크리스트

### 6.1 구분

- 프로젝트 공통 체크리스트: 제작 기간 전체에 한 번 확인하는 항목
- 공연 회차별 체크리스트: 각 회차 시작 전 다시 확인해야 하는 항목

### 6.2 항목 정보

- 공연 프로젝트 또는 공연 회차
- 담당 팀
- 항목 내용
- 필수 여부
- 표시 순서
- 완료 여부
- 완료자와 완료 시각

체크리스트도 개인에게 배정하지 않고 담당 팀에 배정한다. 담당 팀 부원이 완료 상태를 변경하며, 팀장과 운영진이 항목을 관리한다.

### 6.3 권한

- 일반 부원: 전체 조회, 소속 팀 항목 완료·취소
- 팀장: 소속 팀 항목 생성·수정·삭제·상태 변경
- 운영진: 전체 항목 관리

완료 취소를 포함한 상태 변경 이력을 보존한다. 반복 템플릿은 2차 기능으로 둔다.

## 7. 외부 공연 홍보 페이지

### 7.1 목적

외부 관람객에게 작품의 분위기와 제작 정보를 전달하고, 관심 형성부터 회차 확인과 관람 신청까지 하나의 흐름으로 연결한다.

외부 홍보 페이지는 내부 관리자 화면을 그대로 노출하는 페이지가 아니라 학기별 공연 제작 프로젝트마다 발행하는 공연 전용 마이크로사이트다.

### 7.2 조사 근거

- [Hamilton Cast Board](https://hamiltonmusical.com/us-tour/cast-board-angelica/)와 [Moulin Rouge Cast Board](https://moulinrougemusical.com/us-tour/cast-board/)는 특정 공연 일시의 실제 배역과 출연자를 연결한다.
- [Hadestown Cast](https://hadestown.com/broadway-cast)는 배우 사진, 배역과 소개를 작품 홍보 콘텐츠로 사용한다.
- [Royal Shakespeare Company](https://www.rsc.org.uk/the-winters-tale/cast-and-creatives)는 출연진·제작진과 함께 작품 소개, 프로덕션 사진, 리뷰, 트레일러와 접근성 공연 정보를 연결한다.
- [국립극단 공연소개](https://www.ntck.or.kr/ko/performance/info/257322)는 포스터, 장소, 러닝타임, 관람 연령, 자막, 예매 마감, 지연 입장, 촬영 제한, 오시는 길, 시놉시스와 제작진을 함께 제공한다.
- [Chicago 공식 사이트](https://chicagothemusical.com/)는 공연 캘린더에서 회차 선택과 예매 행동을 직접 연결한다.
- [Google Event 구조화 데이터 가이드](https://developers.google.com/search/docs/appearance/structured-data/event)는 여러 공연 회차가 있으면 회차별 Event 정보를 제공하도록 안내한다.

### 7.3 정보 구조

```text
외부 공연 홍보 페이지
├── 공연 메인 비주얼
├── 핵심 공연 정보
├── 작품 소개와 시놉시스
├── 캐스팅 보드
├── 회차별 캐스팅
├── 크리에이티브·스태프
├── 공연 사진·영상
├── 공연 일정·관람 신청
├── 관람 안내·접근성
├── 공연 관련 공시
└── 장소·문의·주최 정보
```

각 섹션은 관객의 질문 하나에 답해야 한다. 설명을 채우기 위한 반복 카드나 기능 소개 섹션은 만들지 않는다.

### 7.4 공개 경로와 상태

- 공연 프로젝트마다 사람이 읽을 수 있는 공개 슬러그를 가진다.
- 공개 페이지 경로 예시는 `/performances/{slug}`로 한다.
- 페이지 상태는 `작성 중`, `공개 예정`, `공개`, `공연 종료`, `보관`으로 관리한다.
- `작성 중` 페이지는 운영진 미리보기에서만 접근한다.
- 공연 종료 후에도 포스터, 캐스팅과 제작진을 기록 페이지로 유지하되 관람 신청 버튼은 제거한다.
- 공연 취소 시 페이지를 삭제하지 않고 취소 상태와 공시를 명확히 표시한다.

### 7.5 메인 비주얼

첫 화면에는 다음 정보를 표시한다.

- 공연 포스터 또는 대표 키아트
- 작품명
- 공연 기간
- 공연장
- 관람 신청 상태
- `관람 신청하기` 행동 버튼

Bandi의 공개 상단 내비와 기본 접근성 규칙은 유지하되, 본문은 해당 작품의 포스터와 키아트를 중심으로 구성한다.

운영진이 페이지별 CSS를 입력하지는 않는다. 대표 이미지, 선택 가능한 제한된 강조색과 콘텐츠 순서만 관리한다.

### 7.6 핵심 공연 정보

다음 정보를 짧은 요약 영역에서 확인할 수 있게 한다.

- 장르
- 공연 기간과 회차
- 러닝타임과 인터미션
- 관람 연령
- 공연 장소
- 관람료 또는 무료 여부
- 신청 시작·마감
- 문의처

핵심 정보는 긴 소개문보다 앞에 배치하며 모바일에서도 접기 없이 확인할 수 있어야 한다.

### 7.7 작품 소개

- 짧은 작품 소개
- 상세 시놉시스
- 연출 의도
- 원작·각색 정보
- 작품 배경과 관람 포인트
- 필요한 경우 스포일러가 포함된 상세 설명

긴 시놉시스는 요약과 상세를 분리한다. 작품 설명과 회차·장소 같은 사실 정보를 중복 작성하지 않는다.

### 7.8 캐스팅 보드

#### 주요 배역

주요 배역에는 다음 정보를 제공한다.

- 배역명
- 배우명 또는 공개 활동명
- 프로필 사진
- 캐릭터 소개
- 배우 소개
- 출연 예정 회차

모든 출연자를 같은 크기의 카드로 반복하지 않는다. 주연, 조연과 앙상블의 정보 위계를 다르게 구성한다.

- 주연: 큰 사진과 배역·인물 소개
- 조연: 중간 크기의 사진과 간결한 소개
- 앙상블: 이름과 역할 중심의 명단

#### 회차별 캐스팅

- 관객이 회차를 선택하면 해당 회차의 실제 배역과 출연자를 표시한다.
- 더블 캐스팅, 대체 배우, 언더스터디와 한 배우의 복수 배역을 표현할 수 있어야 한다.
- 캐스팅 변경이 발생하면 기존 배정을 덮어쓰기만 하지 않고 변경 이력을 남긴다.
- 공연 관련 캐스팅 변경 공시를 해당 회차와 연결한다.
- 관람 신청 단계에서도 선택한 회차의 캐스팅을 다시 확인할 수 있게 한다.

캐스팅 보드는 작품 전체 출연진 소개와 특정 회차의 `오늘의 캐스팅`을 분리한다.

### 7.9 크리에이티브·스태프

배우와 별도로 다음 제작 크레딧을 제공한다.

- 작·원작·각색
- 연출·조연출
- 무대·소품
- 조명·음향
- 의상·분장
- 영상·사진·그래픽 디자인
- 기획·제작

제작진은 배우 카드와 같은 형식을 반복하지 않고 `담당 분야 — 이름` 중심의 공연 프로그램북 형태로 표현한다.

### 7.10 공연 사진·영상

미디어 유형은 다음을 지원한다.

- 포스터와 키아트
- 배우 프로필 사진
- 연습실 사진
- 비하인드 사진
- 트레일러
- 공연 종료 후 무대 사진과 영상

각 미디어에는 제목, 설명, 대체 텍스트, 촬영자·제작자 크레딧과 공개 순서를 기록한다.

영상에는 자막을 제공한다. 무한 자동 재생이나 서사 목적이 없는 캐러셀은 사용하지 않는다.

### 7.11 공연 일정과 관람 신청 연결

- 회차별 날짜와 시간을 표시한다.
- 신청 가능, 마감, 매진과 취소 상태를 구분한다.
- 잔여 좌석을 표시한다.
- 회차별 캐스팅과 접근성 지원 정보를 함께 표시한다.
- 회차를 선택하면 해당 회차의 좌석 선택 단계로 이동한다.
- 모바일에서는 현재 선택 회차와 관람 신청 행동을 쉽게 다시 찾을 수 있게 한다.

홍보 페이지의 주요 행동은 `관람 신청하기` 하나로 유지한다. 동일한 의미의 여러 행동 문구를 섞지 않는다.

### 7.12 관람 안내와 접근성

다음 정보를 공연별로 관리한다.

- 관람 연령과 확인 방법
- 러닝타임과 인터미션
- 입장 시작 시각
- 지연 입장과 재입장 정책
- 공연 중 촬영과 녹음 정책
- 음식물 반입 정책
- 관람 신청 취소 마감
- 신청번호·신분 확인 여부
- 주차와 대중교통
- 휠체어 접근과 접근성 좌석
- 자막, 수어와 기타 접근성 지원 회차
- 큰 소리, 섬광, 연기와 민감한 내용에 대한 주의사항

중요 제한은 긴 약관 안에 숨기지 않고 관람 신청 전에 다시 확인시킨다.

### 7.13 공연 관련 공시

공시 게시판 중 현재 공연 프로젝트와 연결된 항목만 홍보 페이지에 표시한다.

- 캐스팅 변경
- 관람 신청 시작·마감
- 추가 회차
- 매진과 취소표 안내
- 공연 시간·장소 변경
- 공연 취소
- 입장 방법과 관람 유의사항

내부 공지 게시판의 내용은 외부 홍보 페이지에 노출하지 않는다.

### 7.14 장소·문의·주최 정보

- 공연장명과 주소
- 지도 또는 외부 지도 링크
- 대중교통과 주차 안내
- 문의 연락처
- 주최·주관·후원
- 동아리 공식 채널

위치 정보는 공연명과 혼동되지 않는 실제 공연장 정보를 사용한다.

### 7.15 공개 프로필과 개인정보

- 내부 멤버 프로필을 외부 캐스팅 보드에 자동 노출하지 않는다.
- 출연자와 제작진은 공개 이름, 사진, 소개와 SNS 링크를 별도 공개 프로필로 관리한다.
- 이름·사진·소개·SNS의 공개 범위를 항목별로 동의받는다.
- 공개 동의를 철회한 경우 새 노출을 중단하되 이미 종료된 공연 기록의 보존 정책은 별도로 정한다.
- 학교 학번, 연락처, 내부 팀 권한과 회비 정보는 외부에 노출하지 않는다.

### 7.16 운영진 관리 기능

운영진은 다음 항목을 관리한다.

- 공개 슬러그와 공개 상태
- 대표 포스터·키아트
- 작품 소개와 연출 의도
- 등장인물과 캐스팅
- 회차별 캐스팅
- 제작진 크레딧
- 사진·영상과 공개 순서
- 관람 안내와 접근성 정보
- 공연 관련 공시 연결
- 검색·공유용 제목, 설명과 대표 이미지
- 공개 전 미리보기

캐스팅과 제작진의 표시 순서는 운영진이 관리하되 공개 동의가 없는 프로필은 선택할 수 없게 한다.

### 7.17 검색·공유 정보

- 공연별 고유 URL, 페이지 제목과 설명을 제공한다.
- 대표 포스터를 소셜 공유 이미지로 사용한다.
- 공연 회차별 날짜, 장소, 상태와 신청 URL을 Event 구조화 데이터로 제공한다.
- 여러 회차가 있으면 회차별 Event 항목을 생성한다.
- 공연 취소 시 기존 날짜와 장소를 삭제하지 않고 취소 상태를 표시한다.
- 공개 페이지는 로그인 없이 접근하고 검색 엔진이 읽을 수 있어야 한다.

### 7.18 반응형·접근성 원칙

- 모바일에서도 작품명, 공연 일시, 장소와 관람 신청 행동이 먼저 보여야 한다.
- 배우 사진에는 대체 텍스트를 제공한다.
- 동영상에는 자막 또는 대체 설명을 제공한다.
- 회차와 캐스팅을 색상만으로 구분하지 않는다.
- 캐스팅 보드와 회차 선택을 키보드로 조작할 수 있어야 한다.
- 자동 재생 영상과 과도한 스크롤 애니메이션을 기본으로 사용하지 않는다.
- 작품의 시각적 개성을 허용하되 텍스트 대비와 포커스 표시를 훼손하지 않는다.

### 7.19 1차 범위

- 메인 비주얼과 핵심 공연 정보
- 작품 소개와 시놉시스
- 주요 배역·조연·앙상블 캐스팅 보드
- 회차별 캐스팅
- 크리에이티브·스태프
- 공연 일정과 관람 신청 연결
- 관람 안내와 접근성 정보
- 공연 관련 공시
- 장소와 문의
- 공개 프로필 동의
- 검색·소셜 공유 메타데이터

### 7.20 추후 범위

- 트레일러와 비하인드 영상
- 리뷰·보도 인용
- 디지털 프로그램북
- 인터뷰와 제작 일지
- 다국어 공연 소개
- 공연 종료 후 아카이브 컬렉션

## 8. 공연 회차와 관람 신청

### 8.1 공연 회차

하나의 학기별 공연 제작 프로젝트에서 여러 공연 회차를 생성한다.

회차 정보 후보:

- 공연 시작 일시
- 관람 신청 시작·마감 시각
- 입장 시작 시각
- 회차 상태
- 좌석 배치 참조

좌석 배치 참조의 구체적인 구조는 별도 기획 결과를 반영한다.

### 8.2 관람 신청

- 외부 관람객은 로그인하지 않고 공연과 회차를 조회한다.
- 회차와 좌석을 선택한다.
- 이름과 연락처를 입력한다.
- 개인정보 수집·이용에 동의한다.
- 신청이 완료되면 신청번호와 입장 QR을 발급한다.
- 좌석 중복 점유는 서버와 DB에서 차단한다.
- 온라인 결제는 1차 범위에서 제외한다.

### 8.3 신청 조회

관람객은 신청 완료 후 다음 정보를 조회할 수 있다.

- 공연과 회차
- 신청 좌석
- 신청 상태
- 입장 상태
- 취소 가능 여부

조회 인증은 추측하기 어려운 신청 조회 토큰을 기본으로 한다. 신청번호와 연락처를 함께 입력하는 보조 조회 방식도 검토한다.

### 8.4 신청 취소

- 관람객은 취소 가능 기한 전까지 직접 신청을 취소할 수 있다.
- 취소된 좌석은 다시 신청 가능한 상태로 반환한다.
- 입장 처리가 시작된 신청은 관람객이 직접 취소할 수 없다.
- 운영진은 예외 상황에서 신청을 취소할 수 있으며 처리 사유를 기록한다.
- 전체 취소와 좌석 일부 취소 중 어떤 방식을 제공할지는 아직 확정하지 않았다.
- 관람객 취소 마감 시각도 별도로 확정한다.

## 9. QR 입장 관리

### 9.1 QR 발급

- 신청 완료 시 예약 단위 QR 하나를 발급한다.
- QR에는 이름, 연락처와 좌석번호를 직접 넣지 않는다.
- QR에는 추측하기 어려운 입장 토큰 또는 해당 토큰을 포함한 URL만 담는다.
- 서버에는 원본 토큰 대신 안전하게 비교 가능한 값을 저장하는 방식을 적용한다.

### 9.2 입장 흐름

1. 운영진이 해당 공연 회차의 입장 관리 화면을 연다.
2. 관람객의 QR을 스캔한다.
3. 서버가 신청 상태와 회차를 확인한다.
4. 신청 좌석 목록과 기존 입장 상태를 표시한다.
5. 운영진이 전체 좌석 또는 실제 입장한 좌석만 선택해 입장 처리한다.
6. 처리자와 입장 시각을 기록한다.

예약 단위 QR 하나를 사용하되 좌석별 입장 상태를 관리한다. 여러 좌석을 한 사람이 신청하고 일행이 나누어 도착하는 상황을 지원하기 위한 구조다.

### 9.3 중복·오류 처리

- 이미 전원 입장한 QR을 다시 스캔하면 기존 입장 완료 정보와 시각을 표시한다.
- 일부만 입장한 QR은 남은 좌석을 표시한다.
- 취소된 신청이나 다른 회차의 QR은 입장 처리하지 않는다.
- QR 인식 실패에 대비해 신청번호·이름 검색을 보조 수단으로 제공한다.
- 운영진은 잘못 처리한 입장을 취소할 수 있으며 사유와 이력을 남긴다.

### 9.4 운영 지표

- 회차별 신청 좌석 수
- 입장 완료 좌석 수
- 미입장 좌석 수
- 일부 입장 신청 수
- 입장률

## 10. 좌석 정책 보류 사항

다음 사항은 별도 좌석 기획 결과가 확정되기 전까지 결정하지 않는다.

- 공연마다 좌석 배치를 새로 만드는 방식
- 공연장 좌석 템플릿을 재사용하는 방식
- 자유석과 지정석 지원 여부
- 좌석 등급과 구역
- 운영진 차단석
- 휠체어석과 접근성 좌석
- 좌석 임시 선점
- 한 신청의 최대 좌석 수

좌석 기획 결과가 나오기 전에는 DB 구조가 특정 방식에 종속되지 않게 한다.

| 신청 좌석 | 하나의 관람 신청에 여러 개 |

## 12. 추가로 확정할 사항

1. 일반 부원이 생성한 팀 업무를 본인만 수정·삭제할지 팀 전체가 수정할지 결정한다.
2. 특별 공연과 방학 공연을 어느 학기 프로젝트에 포함할지 결정한다.
3. 소품·장비에서 수량 품목과 개별 장비를 모두 1차에 지원할지 결정한다.
4. 관람객의 신청 취소 마감 시각을 결정한다.
5. 좌석 일부 취소를 지원할지 결정한다.
6. QR을 웹 화면으로만 제공할지 이미지 저장도 허용할지 결정한다.
7. 공연별로 사용할 수 있는 강조색과 시각적 변형 범위를 결정한다.
8. 공개 출연자 프로필의 동의 절차와 공연 종료 후 보존 정책을 결정한다.
9. 더블 캐스팅과 언더스터디를 실제 운영에서 사용하는지 확인한다.
10. 공연 홍보 페이지를 언제 공개하고 캐스팅 미정 상태를 어떻게 표시할지 결정한다.
