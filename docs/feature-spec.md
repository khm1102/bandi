# bandi 기능 정의서

> 문서 상태: 초안(현행 화면 프로토타입 역설계)
> 기준 화면: dev 프로파일에서 제공하는 16개 기능별 JSP 화면
> 작성 기준일: 2026-07-16

## 1. 문서 목적

이 문서는 현재 기능별 JSP 프로토타입에 표현된 화면, 사용자 역할, 데이터와 동작을 기능 단위로 정리한다.
아직 합의된 최종 요구사항이 아니며, 디자인 개편과 실제 개발 범위를 결정하기 위한 기준 초안이다.

기능 상태는 다음과 같이 구분한다.

- **동작**: 프로토타입의 메모리 데이터가 실제로 변경되거나 화면이 갱신된다.
- **표현**: 화면과 버튼은 있으나 안내 토스트만 표시되거나 데이터가 변경되지 않는다.
- **미구현**: 실제 서비스에 필요한 서버 저장, 파일 처리, 알림 등은 구현되어 있지 않다.

## 2. 서비스 개요

bandi는 연극 동아리의 부원 활동과 공연 운영을 한곳에서 관리하는 통합 관리 서비스다.

현재 프로토타입이 다루는 업무 범위는 다음과 같다.

- 동아리 계정 가입과 역할 관리
- 팀별 일정, 일정 조율, 활동 기록
- 자료와 게시글 공유
- 소품·장비 및 대여 물품 관리
- 공연 준비 체크리스트와 행사 출석
- 회비 납부 관리
- 공연 정보, 관람 신청, 좌석, 입장 관리

## 3. 사용자 역할

### 3.1 역할 정의

| 역할 | 설명 | 주요 권한 |
|---|---|---|
| 외부 관람객 | 동아리 계정이 없는 공연 관람 신청자 | 공연 조회, 회차·좌석 선택, 관람 신청 |
| 일반 부원 | 초대코드로 가입한 동아리 구성원 | 공통 정보 조회, 일정 응답, 일반 글 작성, 본인 출석·회비 조회 |
| 팀장 | 팀 운영을 담당하는 부원 | 일반 부원 권한 + 일정·자료·활동·소품·행사·체크리스트 편집 |
| 운영진 | 동아리 전체 운영 담당자 | 전체 기능 + 공연·신청·회비·멤버·권한 관리 |

| 화면 | 외부 관람객 | 일반 부원 | 팀장 | 운영진 |

| 홈 | - | ○ | ○ | ○ |

| 일정 조율 | - | 응답·조회 | 응답·조회·확정 | 응답·조회·확정 |
| 자료실 | - | 조회·다운로드 | 조회·등록 | 조회·등록 |

| 게시판 | - | 조회·일반 글 작성 | 조회·일반 글·공지 작성 | 조회·일반 글·공지 작성 |

## 4. 공통 정책

### 4.1 인증과 가입

- 로그인 입력값은 아이디, 비밀번호, 소속 팀이다.
- 일반 부원과 팀장은 가입 당시 팀과 로그인 시 선택한 팀이 일치해야 한다.
- 운영진은 팀 일치 검사를 하지 않는다.
- 회원가입 입력값은 이름, 소속 팀, 아이디, 비밀번호, 비밀번호 확인, 운영진 초대코드다.
- 회원가입은 필수값, 비밀번호 확인, 아이디 중복, 활성 초대코드를 검증한다.
- 신규 가입자는 초대코드에 연결된 기수의 일반 부원으로 생성된다.
- 로그아웃 시 로그인 상태와 선택 중인 좌석을 초기화한다.

### 4.2 팀과 기수

- 기본 팀은 배우연출, 무대, 오퍼, 디자인, 영상이다.
- 멤버 직접 추가 시 기존 팀을 선택하거나 새 팀명을 입력할 수 있다.
- 기수는 `26-1기`, `26-2기`와 같은 문자열로 관리한다.
- 초대코드는 하나의 기수에 연결되며 활성 또는 사용 중지 상태를 가진다.

### 4.3 화면 구조와 피드백

- 로그인 후 좌측 사이드바와 상단 바가 있는 관리자형 화면을 사용한다.
- 역할에 따라 사이드바 메뉴와 등록·관리 버튼 노출이 달라진다.
- 등록·수정 작업은 모달에서 수행한다.
- 성공, 오류, 간단한 조회 결과는 토스트로 안내한다.
- 내부 화면은 기능별 SSR URL로 이동하며, 필터·탭처럼 공유할 필요가 있는 상태만 쿼리 파라미터로 표현한다.

## 5. 화면별 기능 정의

### F-01. 로그인·회원가입

목적: 동아리 구성원을 인증하고 초대코드 기반으로 신규 부원을 등록한다.

| 구분 | 정의 |
|---|---|
| 로그인 | 아이디·비밀번호·팀을 검증하고 계정 역할로 로그인한다. |
| 회원가입 | 사용자 정보와 활성 초대코드를 검증한 뒤 일반 부원 계정과 멤버 정보를 함께 생성한다. |
| 외부 진입 | 계정 없이 공개 관람 신청 화면으로 이동한다. |
| 오류 | 필수값 누락, 비밀번호 불일치, 아이디 중복, 잘못된 초대코드, 로그인 실패를 안내한다. |

### F-02. 홈 대시보드

목적: 오늘의 운영 현황과 주요 업무 진입점을 요약한다.

- 오늘 일정 건수와 일정 목록을 표시한다.
- 일반 부원·팀장은 본인 회비 납부 항목 수를 표시한다.
- 운영진은 회비 미납 인원과 총 미수납액을 표시한다.
- 대여 물품 반납 대기 건수와 전체 공연 신청 좌석 수를 표시한다.
- 상단 고정 공지, 팀별 진행률, 최근 게시글을 표시한다.
- 일정 조율, 자료실, 소품, 체크리스트로 빠르게 이동한다.
- 팀장·운영진에게 일정 등록 진입 버튼을 노출한다.

현재 한계: 날짜, 오늘 일정, 팀별 진행률은 샘플 값으로 고정되어 있다.

### F-03. 통합 캘린더

목적: 전체 또는 팀별 일정을 월간 캘린더로 확인한다.

- 월 단위 이전·다음 이동을 제공한다.
- 전체, 배우연출, 무대, 오퍼, 디자인, 영상으로 일정을 필터링한다.
- 날짜를 선택하면 해당 날짜의 일정명, 팀, 장소를 안내한다.
- 팀장·운영진은 일정명, 일자, 담당 팀, 장소를 입력해 일정을 등록한다.

현재 한계: 일정 데이터에 연·월 정보가 없고 일자만 있어 월 이동 시에도 같은 일정이 반복 노출된다.

### F-04. 일정 조율

목적: 구성원의 가능한 시간을 모아 최다 인원이 가능한 시간을 추천한다.

- 후보 5일과 4개 시간대의 가능 인원 집계를 색상과 숫자로 표시한다.
- 사용자는 클릭 또는 드래그로 본인의 가능한 시간대를 선택·수정한다.
- 응답 인원과 사용자별 응답 여부를 표시한다.
- 가능 인원이 가장 많은 시간대를 추천한다.
- 팀장·운영진은 추천 시간을 일정으로 확정할 수 있다.

현재 한계: 조율 생성·마감·대상자 설정이 없으며, `이 시간으로 확정`은 안내만 표시하고 캘린더 데이터를 만들지 않는다.

### F-05. 자료실

목적: 대본, 회의록, 홍보물, 영상 등 동아리 자료를 분류해 공유한다.

- 전체, 공지, 대본, 회의록, 홍보물, 공연영상, 연습영상, 기타로 필터링한다.
- 파일명과 표의 텍스트를 기준으로 검색한다.
- 공지 자료는 목록 상단과 별도 중요 공지 배너에 표시한다.
- 전체 사용자는 파일 목록을 조회하고 다운로드를 요청할 수 있다.
- 팀장·운영진은 자료 또는 공지 자료를 등록한다.

현재 한계: 실제 파일 선택·업로드·저장·다운로드는 없으며 파일명과 메타데이터만 메모리에 추가한다.

### F-06. 활동 기록

목적: 팀별 활동 내용을 남겨 불참한 부원도 진행 상황을 확인하게 한다.

- 팀, 날짜, 참여 인원, 활동 내용, 사진 유무를 표시한다.
- 팀장·운영진에게 활동 기록 작성 모달을 제공한다.
- 작성 항목은 활동 내용, 날짜, 참여 인원이다.

현재 한계: 저장 버튼은 성공 안내만 표시하고 목록에 기록을 추가하지 않는다. 사진 첨부도 없다.

### F-07. 커뮤니티·게시판

목적: 공지, 자유 의견, 질문을 구성원끼리 공유한다.

- 전체, 공지, 자유, 질문 카테고리로 필터링한다.
- 일반 글은 모든 구성원이 작성할 수 있다.
- 공지는 팀장·운영진만 작성하며 목록 상단에 고정한다.
- 게시글에 좋아요를 누를 수 있다.
- 작성자, 작성 시점, 제목, 본문, 좋아요 수, 댓글 수를 표시한다.

현재 한계: 상세 화면, 댓글 조회·작성, 좋아요 취소·중복 방지, 글 수정·삭제, 실제 알림 발송은 없다.

### F-08. 소품·장비 관리

목적: 공용 품목의 재고·위치·상태와 부원에게 빌린 개인 물품을 관리한다.

- 품목명, 위치, 분류를 실시간 검색한다.
- 전체, 소품, 의상, 조명장비, 음향장비로 필터링한다.
- 전체 품목 종류, 사용 수량, 보관 수량, 반납 대기 건수를 요약한다.
- 모든 구성원은 품목명, 분류, 총수량, 사용 수량, 위치, 상태를 조회한다.
- 팀장·운영진은 품목을 등록·수정·삭제한다.
- 품목 상태는 정상, 사용중, 수선중 중 하나다.
- 팀장·운영진은 부원에게 빌린 물품의 소유자, 대여일, 반납 예정일을 기록하고 반납 완료 처리한다.

현재 한계: 삭제 확인, 이력, 수량 변경 이력, 반납 취소 기능은 없다.

### F-09. 공개 공연·관람 신청

목적: 외부 관람객에게 공연 정보를 제공하고 회차별 좌석 신청을 받는다.

- 공연 제목, 장소, 기간, 시간, 관람 연령, 러닝타임, 작품 소개를 표시한다.
- 6월 21일과 6월 22일 회차 중 하나를 선택한다.
- 좌석은 A~F열, 열당 8석인 총 48석으로 표시한다.
- 신청 완료 좌석은 선택할 수 없고 회차별 잔여 좌석을 표시한다.
- 한 신청에서 최대 6석까지 선택할 수 있다.
- 이름과 연락처를 입력해 선택 좌석을 신청한다.
- 신청 완료 후 좌석을 점유 처리하고 운영진 신청 명단에 추가한다.

현재 한계: 공개 화면의 공연 소개·일정·문의 메뉴는 이동하지 않는다. 연락처 형식, 중복 신청, 개인정보 동의, 신청 조회·취소, 매진 동시성 제어가 없다.

### F-10. 공연 신청 관리

목적: 운영진이 회차별 관람 신청 명단과 좌석 수를 확인한다.

- 총 신청 건수와 총 신청 좌석 수를 표시한다.
- 회차별 신청 좌석 수를 표시한다.
- 관람객명, 연락처, 좌석, 인원, 관람일, 시간을 목록으로 제공한다.
- 신청 명단 내보내기 버튼을 제공한다.

현재 한계: 내보내기는 안내만 표시하며 실제 CSV 파일을 만들지 않는다. 검색, 취소, 수정 기능이 없다.

### F-11. 공연 운영

목적: 운영진이 공연 정보와 공연 당일 입장 상태를 관리한다.

- 공연명, 기간, 시간, 장소, 관람 연령, 러닝타임, 상태, 소개, 이미지를 등록·수정·삭제한다.
- 공연 상태는 준비 중, 신청 진행 중, 마감으로 구분한다.
- 신청 건수, 신청 좌석, 입장 완료, 미입장, 입장률을 요약한다.
- 신청자별 좌석, 회차, 입장 여부, 입장 시각을 표시한다.
- 관람객을 입장 완료 처리하거나 입장 취소 처리한다.

현재 한계: 공연 이미지와 정보는 공개 관람 신청 화면에 연동되지 않는다. 공연 삭제 확인과 회차·좌석 구조 설정도 없다.

### F-12. 공연 체크리스트

목적: 공연 직전 팀별 준비 항목의 완료 상태를 공유한다.

- 전체 완료율과 팀별 완료 수를 표시한다.
- 모든 구성원이 항목의 완료·미완료 상태를 전환한다.
- 팀장·운영진은 담당 팀을 지정해 항목을 추가하거나 삭제한다.

현재 한계: 변경자·변경 시각, 마감, 정렬, 항목 수정, 삭제 확인이 없다. 일반 부원의 완료 상태 변경 허용 여부는 확정이 필요하다.

### F-13. 행사·출석 관리

목적: 회식, MT 등 행사별 참가 현황을 확인한다.

- 행사명, 날짜, 장소, 체크인 인원과 명단을 표시한다.
- 구성원은 본인을 체크인한다.
- 팀장·운영진은 행사명, 날짜, 장소를 입력해 행사를 생성한다.

현재 한계: 체크인 취소, 대리 체크인, 출석 대상자, QR·코드 검증, 행사 수정·삭제가 없다.

### F-14. 회비

목적: 구성원은 본인 납부 현황을 확인하고 운영진은 전체 수납 상태를 관리한다.

일반 부원·팀장:

- 전체 항목 수, 납부 완료 수, 미납 수를 표시한다.
- 항목명, 기준 시기, 금액, 납부 여부, 납부일을 조회한다.

운영진:

- 회비 항목명, 금액, 기준 시기를 입력해 항목을 추가한다.
- 항목별 납부 인원, 미납 인원, 수납액을 표시한다.
- 전체 또는 선택한 부원을 일괄 납부·미납 처리한다.
- 현재 회비 항목을 삭제한다.

현재 한계: 납부 기한, 계좌·결제, 영수증, 납부 이력, 부분 납부, 환불, 항목 삭제 확인이 없다.

### F-15. 멤버·권한

목적: 운영진이 부원 소속과 권한, 가입 초대코드를 관리한다.

- 전체 부원 수, 기수 수, 활성 초대코드 수를 표시한다.
- 이름, 팀, 기수, 역할을 입력해 부원을 직접 추가한다.
- 부원 역할을 일반 부원, 팀장, 운영진 중 하나로 변경한다.
- 기수를 입력해 가입용 초대코드를 생성한다.
- 초대코드를 복사하고 활성화하거나 사용 중지한다.
- 초대코드별 생성일, 가입 인원, 상태를 표시한다.

현재 한계: 계정과 멤버의 직접 추가 데이터가 연결되지 않으며, 추가된 멤버는 로그인할 계정이 없다. 멤버 수정·탈퇴·삭제, 팀 관리, 권한 변경 보호 정책이 없다.

## 7. 현행 프로토타입의 기술적 범위

- HTML 한 파일에 CSS, 화면 템플릿, 가상 데이터, 이벤트 처리가 모두 포함되어 있다.
- 데이터는 브라우저 메모리에만 있으며 새로고침하면 초기 샘플 데이터로 돌아간다.
- 서버 API, 데이터베이스, 세션 인증, 실제 파일 저장은 연결되어 있지 않다.
- 권한 제어는 버튼 노출과 클라이언트 라우팅 수준이라 보안 수단으로 사용할 수 없다.
- 공연·일정·좌석·인원 등 여러 값이 2025년 6월 샘플에 고정되어 있다.

## 8. 디자인 개편 전 확정이 필요한 사항

다음 항목은 화면 구조와 정보 우선순위에 직접 영향을 주므로 디자인 작업 전에 결정하는 것이 좋다.

1. 핵심 사용자와 1차 출시 범위: 부원 운영 중심인지 공연 예매 중심인지
2. 팀장 권한 범위: 자기 팀만 편집하는지 전체 팀을 편집하는지
3. 공연 단위 구조: 여러 공연과 여러 회차를 동시에 운영할 수 있는지
4. 일정과 일정 조율의 관계: 조율 확정 시 캘린더 일정으로 자동 생성할지
5. 자료실과 게시판 공지의 관계: 공지를 하나로 통합할지 별도로 유지할지
6. 소품 관리 범위: 재고 관리와 개인 대여 기록을 한 화면에 유지할지
7. 출석 방식: 자가 체크인, 운영진 확인, QR 중 어떤 방식을 사용할지
8. 회비 범위: 단순 수기 납부 확인인지 실제 결제까지 포함할지
9. 관람 신청 정책: 신청 조회·취소, 개인정보 동의, 중복 신청, 좌석 선점 시간
10. 홈 대시보드의 역할별 핵심 지표와 우선순위

## 9. 프로토타입상 불일치 및 결함 후보

- 팀장 사이드바에 멤버·권한 메뉴가 표시되지만 실제 접근은 차단된다.
- 활동 기록 저장은 목록 데이터를 변경하지 않는다.
- 일정 조율 확정은 캘린더에 일정을 만들지 않는다.
- 자료 업로드·다운로드, 공지 알림, CSV 내보내기는 실제 처리 없이 안내만 표시한다.
- 공연 운영에서 수정한 공연 정보가 공개 관람 신청 화면에 반영되지 않는다.
- 캘린더 일정에 연·월이 없어 다른 달에서도 동일한 일자 데이터가 보인다.
- 멤버 직접 추가는 로그인 계정을 생성하지 않아 멤버와 계정 데이터가 분리된다.
- 게시판 댓글 수는 표시되지만 댓글 기능은 없다.
- 일반 부원도 모든 팀의 체크리스트 완료 상태를 바꿀 수 있다.
- 삭제와 권한 변경 등 영향이 큰 작업에 확인 절차가 없다.
